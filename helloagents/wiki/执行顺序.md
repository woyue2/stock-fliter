# 执行顺序指南（Stocks Filter）

> 本文说明从「获取数据」到「查看报告与搜索」的一套推荐执行顺序，方便日常复盘和排查问题。

> 提示：如果不想手动切目录跑每个模块，可以优先使用根目录的一键脚本：
> `python run_all_strategies.py`  
> 该脚本会依次执行：
> - `get-data/main.py --all`  
> - `check-trend-bottom/main.py --skip-fetch --no-open`  
> - `check-steady-uptrend/main.py --skip-fetch`  
> - `check-new-indicators/main.py`  
> - `scripts/build_reports_index.py`（生成/更新报告索引）  

## 一、首次完整跑一遍（初始化）

1. 环境检查（可选）  
   - 在仓库根目录执行：`python diagnose.py`，确认外部数据接口和网络环境正常。

2. 获取全市场数据（必做）  
   - 进入数据中心：`cd get-data`  
   - 首次运行（或需要全量刷新时）：`python main.py --all`  
   - 输出：`get-data/data/raw/*.csv`，作为后续所有分析模块的统一数据源（SSOT）。

3. 运行核心分析模块（推荐顺序）  
   - 模块 A：TD 九底 / 趋势衰竭  
     - `cd check-trend-bottom`  
     - 使用本地数据：`python main.py --skip-fetch`  
     - 输出：`check-trend-bottom/output/` 下的 CSV / HTML 报告，并写入跨报告索引。  
   - 模块 B：稳步上升 / 趋势突破  
     - `cd check-steady-uptrend`  
     - 使用本地数据：`python main.py --skip-fetch`  
     - 输出：`check-steady-uptrend/output/` 下的报告，并写入跨报告索引。  
   - 模块 C：新指标实验（可选但推荐）  
     - `cd check-new-indicators`  
     - 运行：`python main.py`  
     - 输出：`check-new-indicators/output/` 下的报告，并写入跨报告索引。  
   - 说明：三个分析模块互相独立，仅依赖 `get-data` 生成的数据；顺序不影响结果，此处只是推荐顺序。

4. 对比 TD 九底 vs 稳步上升（可选）  
   - 回到根目录：`cd ..`（确保在仓库根目录）  
   - 执行：`python compare_modules.py`  
   - 输出：`comparison_results/` 下的 Markdown / HTML，对比两个核心模块的重合股票。

5. 生成/更新报告索引  
   - 在根目录执行：`python scripts/build_reports_index.py`  
   - 功能：扫描各模块最新报告，生成/更新 `reports_list.html` 和 `report_index/` 下的按日期快照。  

6. 启动跨报告搜索 API（可视化汇总）  
   - 在根目录启动服务：`python api_server.py`（或双击 `start_api.bat`）  
   - 浏览器中打开 `reports_index.html`：  
     - 可按「代码 / 名称 / 日期 / 模块」搜索股票跨报告记录  
     - 可查看热门股票与整体统计信息  
   - 索引文件：`get-data/data/stocks_index/{YYYY-MM-DD}/stocks_index.csv`  
     - 由各模块在生成 HTML 报告时自动追加更新  
     - 目录名中的 `{YYYY-MM-DD}` 是**股票数据日期**（例如 2026-01-30），不是报告生成日期  
     - `api_server.py` 会自动选择**最新有数据日期**对应目录下的 `stocks_index.csv` 作为数据源。

7. 其他分析模块（可按需运行）  
   - 市场情绪与模式分析：`check-market-sentiment/`（在已有报告基础上做更高层分析）。  
   - 历史 MVP / 实验性脚本：如 `stocks-analyzer-mvp/`、`作用：选股others/` 等，目前不在主流程中，仅供探索和试验。

## 二、日常复盘的最小流程（每天/每次收盘后）

1. 更新数据  
   - 进入 `get-data`：`cd get-data`  
   - 执行增量更新：`python main.py`（默认对全市场做增量更新；也可以显式使用 `python main.py --all`）。

2. 根据需要选择运行的分析模块  
   - 如果只关心趋势拐点：运行 `check-trend-bottom/main.py --skip-fetch`  
   - 如果只关心稳步上升与突破：运行 `check-steady-uptrend/main.py --skip-fetch`  
   - 如果想同步更新跨报告搜索效果：建议三个模块都跑一次（含 `check-new-indicators/main.py`）。

3. 生成/更新报告索引  
   - 在根目录执行：`python scripts/build_reports_index.py` 或直接使用一键脚本：  
     - `python run_all_strategies.py --skip-get-data`  
   - 确保 `reports_list.html` 与 `report_index/` 中的索引是最新的。  

4. 查看报告与搜索  
   - 报告：直接打开各模块 `output/` 目录下的 HTML 报告。  
   - 跨报告搜索：确保 `api_server.py` 在运行，刷新浏览器中的 `reports_index.html`，按股票或日期快速检索历史记录。

## 三、排查问题时的建议顺序

1. 检查数据是否最新：确认 `get-data/main.py --all` 最近是否成功执行。  
2. 检查单个模块输出：查看相应 `output/` 目录是否有最新日期的报告。  
3. 检查索引文件：确认 `get-data/data/stocks_index/{最新有数据日期}/stocks_index.csv` 是否存在且更新时间正确（注意这里的日期是数据日期，而非报告生成日期）。  
4. 检查报告索引：确认最近一次已成功运行 `scripts/build_reports_index.py`（或通过 `run_all_strategies.py` 间接执行），`reports_list.html` 中能看到最新数据日期。  
5. 最后检查 API：若搜索异常，重启 `api_server.py`，观察终端日志中是否有错误信息。
