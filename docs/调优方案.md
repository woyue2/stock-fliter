1. 多进程并发扫描 (推荐，收益极大)
我在查看 

check-volupxyangxshipan/pipeline.py
 和其它模块（如 check-td）时发现，目前的股票扫描主要是单线程串行的（for path in files: load_df... evaluate_stock... ）。按照目前几十次每秒的 it/s 速度，扫完全市场近 5300 只股票将耗费 1 到 2 分钟。

调优方案：我们可以利用 concurrent.futures.ProcessPoolExecutor 给所有的指标扫描核心包裹上一层多进程池。现代家用电脑大多是 8 核或 16 线程以上，这能直接把扫描耗时成比例缩减 4-8 倍，实现几十秒内扫完所有策略！
2. 淘汰 CSV，迈向 Parquet (极致的 I/O 速度)
目前在 get-data 拉取数据以及策略产出时，大家高度依赖 pandas 的 .csv 文件。CSV 不仅体积大，而且每一次 pd.read_csv() 都要经过大量的“字符串解析为浮点数”的过程，非常极其耗时。

调优方案：把 get-data 以及每日中间产物的落盘格式从 .csv 改为 .parquet。Parquet 是列式二进制存储格式，它的读写速度是 CSV 的 10 到 50 倍，且生成的体积通常只有原来 CSV 的 1/5 甚至更小。这样 check-xxx 每次跑策略时数据加载速度如同瞬间完成。
3. 数据计算“向量化” (代码级提速)
如果历史的指标算法（比如各种 indicators.py 或规则判断）底层有用到 for index, row in df.iterrows(): 逐行扫描的代码，这是 pandas 中最著名性能瓶颈点。

调优方案：将其平替为 itertuples()（速度百倍跃升） 或者纯利用原生 Pandas 向量化操作（例如 np.where 和 df.shift()）。这能针对性消除“特定策略运行特别慢”的结节。
4. 消除重复加载机制
在你的 

run_all_strategies.py
 统筹脚本下，目前 check-td, check-tdxmacdxvolume, check-volupxyangxshipan 三个进程启动时，各自都会独立从对应源目录里 load_stock_df 去硬盘里面去拉长达数年的 K 线一次。一千次磁盘 I/O 被跑了 3 遍。

调优方案（进阶）：如果打算做长线整合，可以把数据拉取统一提取为一个“全局预加载内存池”或者共享内存层，使得所有子分析器共享这份 DataFrame 内容，而无需各自分离读取。
